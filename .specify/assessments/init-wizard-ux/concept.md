# 可选做法

## 做法 A — 统一主机顺位驱动架构（以 Host 为一等公民，向导与日常高度一致，彻底消灭 `-1` 与网络策略包袱）

- **做法概览**：
  1. **概念与模型归一**：彻底废除“网络策略”、“局域网/远程”等虚构概念，消除所有对 Tailscale 的特殊硬编码。数据模型严格以“主机（Host：顺位优先级、主机地址、可选别名、端口、超时、归属的 SMB 共享）”为单一真理。
  2. **向导与管理复用统一引擎**：无论是首次运行向导（`--init`）还是日常管理（`--config`）中的新增主机与共享，共用同一套底层组件——先从系统已挂载 SMB 倒推去重的主机列表 ➔ 用户按顺位选主机 ➔ 多选该主机下的 SMB ➔ 保存并标记完成；手动输入 IP/域名仅作未挂载时的兜底，且仅在手动录入时适度给出钥匙串凭证提示。
  3. **基于 URL 的零误伤挂载点净化**：以 SMB URL 的真实共享名为真理来源，自动合成标准挂载点 `/Volumes/<ShareName>`，彻底屏蔽并清洗掉 macOS 本地临时追加的 `-1`、`-2` 等幽灵后缀，且 100% 绝不误伤形如 `project-1` 等合法共享名；存量配置在原地启动时自动清洗。
  4. **全系统 Esc 键即时放弃机制**：基于现有 `TerminalUI.setRawMode` 基础设施，封装轻量安全行读取工具（`promptLineWithCancel`），全系统任何手动输入环节按下 Esc 键均能立即清行并安全返回上层菜单。
  5. **健全状态机与意愿尊重**：解绑“空主机”与“配置损坏”，空列表视为合法休眠状态（后台服务记录休眠日志并状态码 0 退出，不报错，不拉起向导）；修复向导“暂不部署”时的硬编码强装 Bug。
- **投入量级**：`medium`（几天，属于结构治理与统一组件提取，逻辑清晰，改动面完全可控）
- **取舍**：
  - **收益**：彻底解决全部 14 项痛点与隐患；向导与日常配置不再两张皮；概念干净，心智负担降至最低；100% 杜绝 `-1` 污染。
  - **代价/风险**：需要对现有终端输入做轻量重构以支持 Esc 拦截；需要对老用户的 `automnt.plist` 做好平滑在机原地迁移与路径洗涤。
- **容易失控的地方**：
  - 终端行编辑器若过度设计（例如试图实现复杂的光标左右移动、历史记录回滚或自动补全），会导致代码量与终端兼容性复杂度飙升。必须严格约束为“最小安全行编辑器”（仅支持正常字符追加回显、退格键 Backspace 删除、Esc 键取消返回、Enter 键确认）。

## 做法 B — 表层修复打补丁（只改文案与显式 Bug，保留“网络策略”与既有两步流程）

- **做法概览**：
  不触动核心架构与数据模型。依然保留向导中第 1 步“选择本地挂载目标”和第 2 步“配置远程互联降级策略”，仅在第 1 步对列表做一次粗暴的文本正则过滤（强行剥离 `-1`）；修复向导末尾强装 LaunchAgent 的 Bug；解除“至少保留 1 个策略”的删除限制；文案略作润色。手动输入依然裸调系统 `readLine()`。
- **投入量级**：`small`（1-2 天）
- **取舍**：
  - **收益**：改动最小，风险极低。
  - **代价**：核心痛点完全没有根除！“网络策略”概念债务依然存在，多环境（第 3、4、5 个环境）依然无法灵活支持，向导与日常配置依然严重两张皮，手动输入依然无法 Esc 取消（输入陷阱仍在），且用正则粗暴裁切挂载点存在误伤合法数字共享名的严重风险。
- **容易失控的地方**：正则裁切 `-1` 误伤如 `project-1` 共享；概念债务持续积累，后续维护与向外部用户解释成本极大。

## 做法 C — 激进方案：引入重型 TUI 交互库并构建全屏窗口

- **做法概览**：
  引入第三方重型 TUI 库（类似 curses 或 full-screen TUI 框架），将整个向导与日常配置做成类似图形界面的全屏表单应用。
- **投入量级**：`large`（数周以上）
- **取舍**：
  - **收益**：界面视觉效果现代化。
  - **代价**：严重违背本项目“零第三方依赖、原生单文件 Swift 源码、极致轻量无负担”的黄金准则；全屏 TUI 在不同的终端模拟器（Terminal.app、iTerm2、Warp、VSCode 内置终端等）下存在大量的兼容性、尺寸重绘与闪烁陷阱。
- **容易失控的地方**：跨终端渲染故障、依赖项膨胀、发布二进制体积失控。

# 建议

强烈建议采用**做法 A（统一主机顺位驱动架构）**。

**判断依据**：
1. **全面命中目标**：做法 A 是唯一能够同时达成问题定义中全部 6 大目标、100% 消除 14 项痛点的方案；
2. **第一性原理与架构纯粹**：将虚构的“网络策略”与特化的“Tailscale”彻底清除，统一为纯粹的“主机（Host）”，不仅交互丝滑，而且代码底座大幅精简自洽；
3. **投入产出比最高**：做法 A 仅需在现有 Swift 原生能力下重组选择器与行读取工具，投入量级仅为 `medium`，不需要任何外部库，完全符合开源工具的极简原则；
4. 做法 B 只是扬汤止沸，无法解决两张皮与输入卡死问题；做法 C 则是过度设计的反面典型。

# 明确不做的部分（针对首选做法）

- 坚决不打破主机顺位的排他性（维持命中首个顺位即退出挂载的严格互斥原则，绝不搞跨顺位多机并发挂载）。
- 坚决不为特定组网工具（如 Tailscale）保留专属特化分支，万物平权为标准 Host。
- 坚决不引入第三方重型 TUI 依赖，仅使用 Swift 原生 POSIX termios 与标准 ANSI 序列。
- 不对从已挂载卷宗倒推出来的主机进行多余的钥匙串提示（仅在手动录入未挂载主机时做温和提示）。
- 不在行编辑器中增加复杂的光标漫游、自动补全或多行编辑能力，保持行编辑器的极致轻量安全。

# 需要验证的假设

- 封装的轻量 POSIX termios 行读取工具（`promptLineWithCancel`）在 macOS Terminal.app 与 iTerm2 中处理英文字符、数字、常见符号与退格键时行为完全一致。
- 存量配置文件在启动时，能够在不影响后台守护服务正常评估的前提下，静默将旧的 `local_lan` 等标识与 `/Volumes/xxx-1` 路径平滑清洗升级。
- 当主机列表被用户完全清空后，后台守护进程能够稳定记录休眠日志并以状态码 0 退出，系统 launchd 不会将其误判为服务异常崩溃。
