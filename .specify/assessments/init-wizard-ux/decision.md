# 交接给规格阶段（Handoff to `$speckit-specify`）

- **问题陈述**：向导与日常配置存在严重的工程概念脱节（网络策略/局域网/远程二分法）、数据未去重导致 `-1` 污染配置、新增主机/共享严重两张皮、手动输入无法 Esc 退出，且向导硬编码强装后台服务。
- **选定做法**：**做法 A —— 统一主机顺位驱动架构**（以 Host 为一等公民，向导与日常高度一致，彻底消灭 `-1` 与网络策略包袱）。
- **范围内**：
  1. **纯主机顺位探测模型**：概念与数据结构全面归正为“主机（Host）与从属 SMB 共享”，彻底清除“网络策略”与 Tailscale 特化代码，坚决维持顺位排他性原则；
  2. **统一向导与管理交互引擎**：向导与日常管理统一复用“扫描已挂载 ➔ 倒推主机 ➔ 点选主机 ➔ 勾选名下 SMB ➔ 保存返回”的核心组件；手动输入仅作兜底；
  3. **标准挂载点零误伤净化**：以 SMB URL 真实共享名提取推导 `/Volumes/<ShareName>`，彻底根除 `-1`、`-2` 等临时冲突后缀，且 100% 绝不误伤合法带数字共享名；
  4. **全系统 Esc 键即时放弃机制**：基于 POSIX termios 封装安全轻量输入行，全系统任何文本输入环节按下 Esc 均可立即清行并安全返回上一级；
  5. **健全状态机与意愿遵从**：解绑空主机与损坏判定，空列表合法休眠退出；修复向导无视用户选择强装 LaunchAgent 的 Bug；
  6. **原地平滑洗涤与升级**：存量配置文件在启动时自动原地升级规整，不破坏现有运行中的自动挂载。
- **范围外**：
  1. 坚决不打破顺位排他性（不搞并发探测与跨顺位并发挂载）；
  2. 坚决不为 Tailscale 等特定组网工具搞特殊化适配；
  3. 不对从已挂载卷宗倒推出来的主机进行多余的钥匙串密码提示；
  4. 坚决不引入第三方重型 TUI 框架。
- **成功指标**：向导第一步零歧义；挂载点后缀净化率 100%；Esc 键退出覆盖率 100%；用户部署意愿遵从率 100%；空配置休眠稳定性 100%。
- **带过去的待答问题与待验证假设**：
  1. POSIX termios 轻量行编辑在多终端退格与 Esc 响应的稳定性；
  2. 存量配置文件原地升级时，静默清洗历史遗留的 `/Volumes/xxx-1` 路径的逻辑完备性。
