# 问题陈述

现有的初始化向导与日常配置管理在交互模型、概念认知和终端操作体验上存在系统性脱节：
一方面，向导与日常菜单强推过时的“网络策略”、“局域网/远程”等虚构工程概念，不仅在列表呈现中直接暴露底层未去重的系统临时挂载点并导致 `-1` 等冲突后缀污染持久化配置，而且在新增主机和共享时严重割裂脱节、强迫手敲长字符串；特别是在配置主机时将底层实现字段无加工推给用户，强迫连续键入“内部标识符 (id)”与“描述名称”，产生极易重复且毫无意义的双重输入负担；
另一方面，终端交互缺乏容错，所有文本输入环节均无法按 Esc 键放弃退出，向导末尾甚至无视用户意愿强行部署自启动后台服务。这些缺陷使用户在首次配置和日常维护时面临极高的认知负荷与操作挫败感。

# 受影响的使用者与相关方

- **使用者：项目维护者本人** — 亲自以终端用户视角走访向导与配置菜单，遭遇了误勾选远程卷宗导致配置污染、输入无法 Esc 退出、不可删空策略等一系列严重体验障碍。— [source: intake.md]
- **使用者：外部 Mac 终端用户** — 面对非人性的向导列表（同名共享、`-1` 后缀混杂）、生涩晦涩的“远程降级策略”术语，极易选错导致挂载异常；且因缺乏 Esc 放弃机制容易产生被卡死感。— [source: intake.md, research.md]
- **相关方：项目维护者（产品决策者）** — 拥有产品业务规则与交互哲学的最终决定权，明确确立了“排他性顺位探测”为不可动摇的刚性需求，并定调“全面消除 Tailscale 特化、回归纯粹 Host 模型”。— [source: intake.md, 会话指示]

# 目标

1. **统一归正为“纯主机顺位探测模型”**：彻底清除“网络策略”、“局域网直连”、“远程降级”等陈旧术语，全系统仅保留“主机（Host）”与“SMB 共享（Shares）”，明确共享归属于主机；运行时坚持严格的顺位排他探测（首个通则挂载，后续备用绝不自动挂载）。
2. **打造“主机优先（Host-First）+ 循环登记”的自然向导流**：初始化向导与日常管理高度统一。先从系统已挂载 SMB 倒推去重的主机列表 ➔ 用户选主机 ➔ 可选输入人类友好别名（直接回车默认采用主机地址作为显示名，彻底废除内部 id 与描述的双重冗余输入） ➔ 多选该主机下的 SMB ➔ 保存并标记完成；手动输入仅作未挂载时的纯粹兜底。
3. **实现基于 SMB URL 的标准挂载点零误伤净化**：以 SMB URL 的真实共享名为单一真实来源，自动合成标准挂载点 `/Volumes/<ShareName>`，彻底屏蔽并清洗掉 macOS 本地临时追加的 `-1`、`-2` 等幽灵后缀，且 100% 不误伤自身带数字的合法共享名。
4. **终端全局文本输入支持 Esc 键即时放弃**：在 POSIX termios 机制下封装安全行输入组件，全系统任何手动输入环节均可按 Esc 退出并优雅返回上一级，彻底杜绝强行回车或按 Ctrl+C 强退。
5. **解绑“空主机”与“配置损坏”，尊重用户全部意愿**：允许用户删空所有主机，空配置作为合法休眠状态（后台服务记录休眠日志并状态码 0 退出，不报错，不拉起向导）；向导严格尊重用户“暂不部署后台服务”的选择，修复硬编码强装 Bug。
6. **存量配置平滑无感兼容升级**：老用户的 `automnt.plist`（含 `profiles` 等旧结构或 `-1` 历史路径）在启动时自动原地升级规整，不破坏现有运行中的自动挂载。

# 非目标

1. **不改变多主机并发挂载**：坚决不搞跨顺位多主机并发探测与同时挂载，维持现有的单策略 break 强排他性（首个通畅则备选顺位坚决不挂）。
2. **不为特定组网工具（如 Tailscale）搞特殊化适配**：彻底废除 `discoverTailscalePeers` 等特化代码，任何组网工具在系统中一视同仁为标准 Host（IP/域名 + 端口）。
3. **不对已挂载的主机进行多余的钥匙串提示**：对于能从当前已挂载 SMB 倒推出来的主机和共享，因钥匙串必定已有凭证，坚决不作任何干扰提示（仅在手动输入未挂载的新 IP 时做温和提示）。
4. **不引入复杂的第三方 TUI 依赖（如 ncurses）**：坚持使用原生的 Swift POSIX termios 和 ANSI 转义序列实现轻量行编辑，维持单文件无外部依赖的纯粹性。

# 成功指标

1. **向导零歧义率**：向导第一步呈现去重后的主机列表，不再并列出现属于同一物理主机的不同网络入口与 `-1` 后缀卷宗。（基线：直接平铺展示 4 个混杂的底层挂载点）
2. **挂载点后缀净化率 100%**：无论是首次向导还是日常导入，写入配置文件的挂载路径中 0 个出现因系统冲突产生的 `-1`、`-2` 等临时后缀。（基线：直写 `/Volumes/finalhome-1`）
3. **Esc 键退出覆盖率 100%**：产品中所有需要手动键盘输入的场景，按 Esc 键均能立即清行并安全返回上层菜单。（基线：0% 覆盖，按 Esc 无法退出）
4. **意愿遵从率 100%**：用户在向导中选择“暂不部署”后，系统 `LaunchAgents` 目录下 0 个写入 plist 文件，launchd 中 0 个注册服务。（基线：必定被强行注册）
5. **空配置休眠稳定性**：清空所有主机后，在终端手动执行 `automnt` 和由系统事件唤起后台服务时，均无报错、无刷屏、无强制弹向导，以状态码 0 干净退出。（基线：报错退出码 2 或强拉向导）

# 不行动的代价

若维持现状，新用户在首次运行时有极高概率因误选 `-1` 卷宗而永久固化错误挂载点并丢失局域网直连；遇到输入错误时因无法 Esc 退出而产生极强的被绑架挫败感；维护者被迫在后续维护中不断忍受“网络策略”与“挂载目标”机制割裂脱节带来的操作繁琐，并随时面临向导强行篡改用户后台服务配置的违背用户意愿风险。
