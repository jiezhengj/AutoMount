# 判定与理由

判定为 **go**。问题有效性、价值对比与可行性均为 strong，证据强度达到 adequate，且已有成形的推荐做法（做法 A），满足进入规格阶段的条件。需要如实标注的弱项有两处：一是需求侧证据薄弱，本评估的结论主要建立在平台与流程约束上，而不是使用者规模上；二是"无 root、无签名地获取链路层信息"这条路径缺少官方文档支持，只有本机实测。这两点不影响"值得进入规格阶段"的判断，但必须作为规格与计划阶段的显式风险与验证项，不能被静默略过。

"需要澄清"一节不适用：本判定为 go。

# 交接给规格阶段

- **问题**：同一套程序与配置在使用者机器上存在多处可运行、可编辑的副本，使用者无法确定哪一份在生效，删除下载文件后也缺少方便的配置入口；升级还会在使用者机器上现场生成程序。
- **选定做法**：做法 A —— 用户级搬迁式安装（安装器把程序安置到用户目录的唯一位置、由安装器自行删除下载副本、写入并可精确还原一条命令入口；升级由程序自行下载预编译程序替换自身）。
- **范围内**：单一程序与单一配置的安装形态；由安装器管理的命令入口；程序自行完成升级且使用者机器不需要编译工具；"未签名程序读不到网关 MAC"这一能力问题在本范围内解决或明确给出替代方式。
- **范围外**：网络识别与挂载逻辑本身；跨平台；第三方包管理器；付费签名与公证；新增常驻进程或图形界面；可双击安装的安装包形态。
- **成功指标**：安装后仅一份生效程序与一份生效配置；删除下载文件后仍有稳定入口；无开发工具环境可完成升级；卸载不留残余；变更进入实施前逐条列出使用者可见影响与系统能力影响；在不购买签名服务的前提下仍能提供网络识别所需能力。
- **带过去的待答问题**：图形界面双击首次运行的实际拦截行为（只在提供可双击交付物时才进入关键路径，本范围内不涉及）；借系统工具获取链路层信息的方式在不同机器与后续系统版本上的稳定性（规格与计划阶段必须作为风险与验证项记录）。
- **待验证假设**（来自 concept.md）：用户目录内的程序可在运行时安全替换自身；命令入口写入幂等且卸载可精确还原；老版本遗留的两份配置能被可靠收敛为一份活动配置；安装器删除自身所在的下载副本不会被系统限制。
