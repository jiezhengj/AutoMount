# 可选做法

## 做法 A — 用户级搬迁式安装（自删下载副本 + 稳定命令入口）

- **做法概览**：使用者仍然下载一个预编译程序并在终端里运行它，但这一步之后就结束了：安装器把程序放到用户目录下唯一的安装位置，配置文件也只保留这一份；安装器自己把"下载来的那一份"删掉，使用者不需要再手工清理；安装器在使用者的 shell 配置里写入一条命令入口（卸载时由卸载流程精确移除），从此再次配置只需敲一个短命令。以后升级由程序自行下载预编译程序并替换自己这一份，不下载源码，也不在使用者机器上编译。
- **投入量级**：small
- **取舍**：换来"程序一份、配置一份、下载副本由安装器自己清掉、命令入口稳定、升级不需要编译工具"，并且不需要管理员密码、不需要付费签名，网络变化触发能力保留。牺牲的是"一步装完"的观感：使用者仍需在终端里跑一条命令（而不是双击安装包）。风险集中在三处：老配置迁移时如何判定哪一份是活动配置；命令入口写入与还原必须精确；程序替换自身时的原子性。
- **容易失控的地方**：把"配置迁移"做成第二套同步机制（这正是要消除的东西）；命令入口的写入在重复安装、换用户名、换 shell 时出现重复行或误删用户内容；自更新在替换可执行文件时的失败恢复。

## 做法 B — 一次授权的标准化安装（安装包 + 系统级位置）

- **做法概览**：使用者下载安装包并双击（或在终端运行安装包），输入一次密码完成安装：程序进入系统级位置，命令入口天然存在于系统搜索路径中，不需要改动 shell 配置；卸载由安装包自带的卸载路径处理。后台服务仍由程序自己注册（保留网络变化触发），需要链路层信息时按已验证的方式交由系统工具读取。
- **投入量级**：medium
- **取舍**：换来最接近"一次装完、以后不用管"的体验，命令入口标准、不必注入 shell 配置。牺牲的是：需要一次管理员授权；程序位于系统目录后，"程序自行升级"与目录写权限冲突——要么每次升级再输一次密码（违反"不要反复输密码"的原始意图），要么引入一个有权限的辅助组件（复杂度与安全面都上升）；另外安装包在未签名情况下首次安装的拦截行为未验证（官方文档只覆盖应用、磁盘映像与安装包，命令行工具情形未有结论）。
- **容易失控的地方**：系统目录权限与自更新之间的矛盾；卸载路径与残留；未签名安装包的首次安装体验；把"一次授权"逐步演变成"常驻特权组件"。

## 做法 C — 最小修复（只更换升级通道）

- **做法概览**：其余全部不动，只把升级从"下载源码并在本机编译"改成"下载预编译程序"。使用者的安装方式、目录结构、双份状态完全保持现状。
- **投入量级**：small
- **取舍**：换来"使用者机器不再需要编译工具"，同时消除现版本与项目原则之间的冲突，改动面最小、风险最低。牺牲的是维护者提出的核心问题：程序与配置仍是两份，删掉下载目录后的入口问题仍在，每次发版仍要处理两边是否一致。
- **容易失控的地方**：几乎没有——但也几乎没有解决什么问题，属于"只做能够立刻确定收益的那一小步"。

# 建议

建议采用**做法 A**。判断依据是它同时命中问题定义里的四条目标：安装后只有一份生效的程序与一份生效的配置；使用者删掉下载文件后仍有稳定入口（而且这一步由安装器自动完成，不需要使用者记得去删）；升级不需要使用者机器具备编译工具；由于不引入系统级位置，也不需要处理"自更新要权限"的矛盾。它同样不需要付费签名，并能保留网络变化触发能力。做法 B 更接近"一步装完"的理想形态，但会把"一次授权"升级为"每次升级都要授权或引入特权组件"，与维护者明确的"不要反复输密码"相冲突，因此列为备选而非首选。做法 C 只值得作为做法 A 的降级预案：一旦做法 A 的实施受阻，可以先落地做法 C 的收益。

# 明确不做的部分（针对首选做法）

- 不改动网络识别与挂载逻辑本身。
- 不做跨平台支持，范围仍是 macOS 27 及以上的 Apple silicon。
- 不引入第三方包管理器，也不把付费签名与公证作为前提。
- 不新增常驻的第二个运行进程，不新增图形界面。
- 不提供"可双击安装"的交付物形态（那属于做法 B 的范围）。
- 不在使用者机器上编译任何源码。

# 需要验证的假设

- 用户目录内的程序能够在运行时安全替换自身（原子替换与失败恢复的可行性需要在实施前验证）。
- 在使用者 shell 配置中写入命令入口是幂等的，卸载时能精确移除且不影响使用者其它配置。
- 老版本遗留的配置（下载目录与安装目录可能各有一份）能够被可靠判定出一份活动配置，并按单一来源原则收敛。
- 通过系统工具获取链路层信息的方式（无 root、无签名）在不同机器与后续系统版本上的稳定性——本机已实测通过，但没有官方文档支持。
- 安装器删除自身所在的下载副本不会遇到"文件正在使用"类限制（需要实测确认）。
