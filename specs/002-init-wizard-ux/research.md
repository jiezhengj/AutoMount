本研究针对 Feature `002-init-wizard-ux` 的核心技术决策进行系统性调研与工程论证。

当前代码库基线版本为 `v3.0.0`。在首次运行初始化向导（`--init`）与日常管理（`--config`）中，系统存在网络策略二分法抽象、卷宗未去重导致的挂载点临时 `-1` 后缀污染、向导与日常配置两套交互机制割裂、缺少 Esc 取消回退机制，以及向导末尾无条件安装 LaunchAgent 等工程债务。

结合维护者在评估阶段的裁决与技术自测结果，本研究深入论证五项核心技术决策：基于 POSIX termios 的轻量级终端输入与 Esc 取消、SMB URL 单一真理与挂载点规整算法、主机优先多主机循环登记流、存量配置原地平滑升舱算法，以及空配置合法化与后台守护服务意愿遵从。

# 决策一：基于 POSIX termios 的轻量字符捕获与 Esc 取消

### 决策内容

程序采用基于 Darwin POSIX 原生终端控制接口的轻量级行输入机制：
1. 封装通用行读取函数 `promptLineWithEsc(prompt: String) -> String?`；
2. 在读取前通过 `isatty(STDIN_FILENO)` 判断标准输入是否为标准交互式终端（TTY）：
   - 若非 TTY（如自动化测试、管道重定向、CI/CD 脚本），立即自动降级为标准流式行读取 `readLine()`，杜绝环境异常；
   - 若为 TTY，通过 `tcgetattr` 读取当前终端属性，保存原始配置并在退出时通过 `defer` 恢复；修改 `termios.c_lflag` 关闭规范模式（`ICANON`）与回显（`ECHO`），设置 `VMIN = 1, VTIME = 0` 进入单字符捕获模式；
3. 循环捕获字符流：
   - 捕获到 ASCII 27 (`\x1b`)：判断是否为单独按下的 `Esc` 键，若是，向终端写入 `\r\u{1B}[K`（回车并清除当前整行），打印 `(已取消)` 并直接返回 `nil`；
   - 捕获到 ASCII 127 (`\x7f`) 或 ASCII 8 (`\x08`)：处理退格，删除缓冲区最后一个字符并向终端回显退格擦除序列 `\u{08} \u{08}`；
   - 捕获到回车换行（`\n` 或 `\r`）：向终端输出换行符，返回当前缓冲区的字符串内容；
   - 其他可打印字符：追加至缓冲区并在终端实时回显。

### 论证与理由

- **单文件零依赖原则**：Darwin 原生包含 `<termios.h>`，Swift 标准库可通过 `import Darwin` 直接无缝调用，代码体积仅约 60 行，执行延迟小于 1ms，完全不需要引入外部三方库。
- **高韧性容错能力**：彻底解决了用户在命令行误触进入某步骤后“无法后悔、只能强行胡乱输入或使用中断键强退丢失全部前置配置”的严重交互问题，提供了专业命令行工具应有的交互质感。
- **管道降级双保险**：通过 `isatty` 检查，确保在非交互式自动化调用时完全不执行终端模式配置，杜绝任何潜在的终端控制错误。

### 评估与否决的替代方案

- **引入 ncurses 或第三方 TUI 库**：否决。严重违背项目“纯原生单文件零第三方依赖”的铁律，大幅增加编译复杂度与二进制体积。
- **沿用原生阻塞式 readLine()**：否决。属于阻塞式封装，在用户按下回车前无法监听键盘事件，无法拦截 `Esc` 键，交互体验极其僵硬。

# 决策二：基于 SMB URL 单一真理推导标准挂载点

### 决策内容

挂载点路径的推导完全与本地系统当前的卷宗挂载状态解耦，以 SMB URL 中的真实共享名作为唯一的单一真理来源（SSOT）：
1. 提取核心算法函数 `deriveStandardMountPoint(from smbUrl: String) -> String`；
2. 通过标准 `URL(string: smbUrl)` 解析路径结构，提取有效路径片段；
3. 获取路径中的末尾非空片段作为标准共享名（`shareName`），规整构造目标挂载点路径 `/Volumes/<shareName>`；
4. 严格禁止在探测或配置生成时直接读取 `/Volumes/xxx-1` 等本地临时冲突路径。

### 论证与理由

- **根除 macOS NetFS 冲突机制的副作用**：macOS 在网络异常断开、Finder 强退或未干净卸载时，可能会在 `/Volumes` 下残留不可见的同名卷宗目录项。当再次挂载同名共享时，NetFS 会自动向后追加 `-1`、`-2` 等后缀以避免覆盖本地目录。若将此类临时冲突后缀持久化到配置文件中，会导致后续断网探测失效、Finder 侧边栏路径混乱。
- **零误伤合法命名**：通过直接从 SMB URL（如 `smb://192.168.1.100/data-1`）中提取真名，由于远端 NAS 上的共享名为 `data-1`，算法推导出的标准路径准确为 `/Volumes/data-1`，从数学逻辑上 100% 杜绝了正则猜切导致的误伤。

### 评估与否决的替代方案

- **基于正则表达式裁剪本地路径末尾后缀**：否决。正则无法分辨末尾的 `-1` 究竟是 macOS 系统为了避让冲突追加的临时后缀，还是用户本身在 NAS 上创建的合法共享名（如 `media-1`、`project-2`），极易造成误伤裁剪。
- **沿用已挂载卷宗本地路径**：否决。这正是导致历史版本在发生挂载冲突后永久污染配置文件的直接根源。

# 决策三：主机优先与多主机循环登记交互引擎

### 决策内容

将初始化向导与日常管理重构为“主机优先 + 扫描倒推 + 循环登记”的统一交互流：
1. **活跃卷宗探测与主机聚类**：从内核挂载表（`getfsstat` / `MNT_NOWAIT`）读取当前系统所有类型为 `smbfs` 的挂载，解析每个卷宗的 SMB 地址，提取主机名（或 IP）与从属共享名，按主机维度自动聚类聚合；
2. **两级下钻选择**：先呈现归纳后的候选主机列表，用户选定某台主机后，再展开该主机名下的未配置共享列表供多选勾选；
3. **循环登记与防重标记**：某台主机配置保存后，系统重新展示候选主机列表，已被配置的主机附带 `[✓] 已配置` 标记且置为不可重复选状态，用户可顺畅继续点选配置第二台主机；
4. **统一跳过与完成入口**：候选主机列表中提供“跳过主机配置（生成合法空配置）”、“完成主机配置并继续”以及“手动录入新主机”选项。

### 论证与理由

- **贴合物理世界心智模型**：用户在管理网络存储时，首先感知的是“物理服务器（家庭 NAS、办公室服务器、远程备份机）”，其次才是服务器上的“共享文件夹”。先选主机再选共享，完全符合第一性原理。
- **支持一次性编排多顺位**：用户往往同时拥有局域网环境与远程互联环境。循环登记让用户在首次向导中即可一次性完整录入第 1 顺位（局域网）与第 2 顺位（远程），无需退出向导后再手工补录。

### 评估与否决的替代方案

- **平铺展示所有已挂载卷宗**：否决。如果用户挂载了同一台 NAS 上的 5 个共享，列表将出现 5 行重复的主机 IP，混杂割裂，无法建立主机与从属共享的清晰归属感。
- **配置单台主机后直接结束流转**：否决。剥夺了用户在向导中配置备用顺位主机的能力，迫使用户在日常配置中再次操作。

# 决策四：存量配置原地平滑升舱算法

### 决策内容

在配置文件加载模块 `loadConfig()` 中植入轻量级配置规范嗅探与原地升舱逻辑：
1. 读取 `automnt.plist` 时，首先检查根字典中是否存在旧版 `profiles` 数组且缺失新版 `hosts` 列表；
2. 若命中旧版格式，启动升舱迁移管线：
   - 遍历各 profile，将其 `description` 映射为新主机的 `alias`；
   - 提取 profile 中的 `timeoutMs` 与 `preventSpotlightIndex`，原样赋予新 `HostConfig`；
   - 遍历各 profile 的 `targets`（SMB 共享），通过 `deriveStandardMountPoint` 重新提取标准挂载点，清洗历史残留的 `/Volumes/xxx-1` 临时后缀；
   - 将配置数据结构封装为包含 `hosts` 数组的新版模型，并更新规范版本标识；
3. 将升舱后的新配置以原子安全写入方式原地重写回 `~/Library/Application Support/automnt/automnt.plist`（保持 `0600` 权限），并在日志中记录平滑升舱提示。

### 论证与理由

- **无感向下兼容**：存量用户升级到新版本程序后，无需重新执行初始化向导，现有自动挂载服务完全不中断。
- **配置数据原地清洗**：老配置中历史累积的 `-1` 污染路径在程序读取的瞬间被全自动纠偏清洗为标准路径，实现无感自愈。
- **恪守单一活动配置宪法**：升舱直接在唯一的活动配置文件上原地完成，绝不生成第二份配置文件，避免配置脱节。

### 评估与否决的替代方案

- **要求存量用户手动重新初始化**：否决。严重损害用户体验，破坏平滑升级承诺。
- **长期保留旧模型双套解析分支**：否决。长期维护两套模型会导致技术债务迅速累积，违背极简架构准则。

# 决策五：空配置合法休眠与部署意愿遵从

### 决策内容

1. **解绑 0 主机与配置损坏**：
   - 判定配置有效的标准为语法结构完备与解析成功，0 台主机定义为合法的空配置状态；
   - 日常管理菜单中允许用户删除所有主机并正常保存退出；
   - 后台事件唤醒评估时，若检测到主机列表为空，向控制台/日志记录一条静默休眠信息，并直接以退出码 0 安全退出本次评估，不报错、不崩溃；
2. **向导部署意愿遵从**：
   - 在向导末尾明确询问用户是否部署后台服务；
   - 若用户选择“暂不部署/稍后自行管理”，函数返回部署状态为 `false`，`main()` 函数检测到该状态后，仅输出成功保存提示并退出，绝对禁止调用 `installLaunchAgent()`。

### 论证与理由

- **符合状态机第一性原理**：“配置为空”属于完全合法的业务状态（例如用户暂时搬离办公场所想停用全部网络挂载）。以往将空列表等同于配置损坏，属于防御过度引起的逻辑扭曲。
- **杜绝未经授权安装**：现存代码在 `main()` 中硬编码无条件调用 `installLaunchAgent()`，严重侵犯用户意愿与系统掌控权。通过严密的状态返回值传递，确保仅在用户显式授权时才向系统安装服务。

### 评估与否决的替代方案

- **强制要求配置中至少保留 1 台主机**：否决。当用户想临时停用所有主机时，被迫输入虚假无效的主机数据，体验极差。
- **向导忽略用户选项始终默认安装后台服务**：否决。违背开源软件基本的安全与隐私伦理。
