# 用户场景与验收测试

## 用户故事 1 - 首次向导的主机优先、循环登记与部署意愿遵从（Priority: P1）

使用者在首次运行或执行 `--init` 初始化向导时，系统不再呈现抽象生涩的“网络策略”、“局域网直连/远程降级”等过时概念，而是以“主机（Host）”为一等公民。向导首先主动扫描系统中当前活跃挂载的 SMB 卷宗，将它们按服务器地址/域名自动归纳并展开为候选主机列表供使用者点选；列表同时提供“手动输入新主机地址”与“跳过主机配置”选项。使用者点选某台主机后，向导提示输入可选的人类友好别名（直接回车默认采用主机地址作为显示名，彻底杜绝要求用户连敲内部标识符 id 与描述名称的双重冗余），随后下钻列出从属于该主机的共享文件夹供多选勾选确认；保存后，向导重新返回候选主机列表，已被选过并配置的主机展示明确的完成标识（如 `[✓] 已配置`）且禁止重复选择。使用者可继续点选配置下一顺位的主机，形成顺位备选列表，亦可选择“完成主机配置并继续”。全流程允许使用者随时跳过主机设置直接进入后续配置。向导在保存配置前，清晰询问使用者是否“立即部署并开机自启后台服务”；若使用者选择“暂不部署/稍后自行配置”，系统仅完成配置落盘并优雅退出，坚决不向系统注册任何后台服务。

**Why this priority**: 首次向导是用户接触产品的第一触点。消除配置污染、支持多主机顺位一次性录入、杜绝后台服务未经授权自启的严重缺陷，是保障用户使用预期与建立产品信任的首要前提。

**Independent Test**: 在一台无任何 `automnt` 配置的设备上运行 `--init` 初始化向导，分别测试“勾选第一台主机及从属共享后返回列表、继续配置第二台主机”、“在初始候选主机列表中直接选择跳过主机配置”流程，以及“在末尾选择暂不部署服务”选项，验证配置是否成功按多主机顺位生成，且系统服务目录下无任何未经确认自动安装的守护配置。

**Acceptance Scenarios**:

1. **Given** 用户当前已在 macOS 系统中手动挂载了多台物理服务器（如局域网 NAS 与远程主机）的 SMB 共享，**When** 用户执行 `automnt --init`，**Then** 向导首先呈现按已挂载卷宗自动归纳提取的主机地址列表，包含所有候选主机、“手动添加新主机”以及“跳过主机配置”选项。
2. **Given** 用户在候选主机列表中选择了第一台主机，**When** 系统提示输入主机别名，**Then** 用户可直接回车默认使用主机地址作为显示名，或输入人类友好别名，系统坚决不向用户索取任何底层内部标识符（`id`）；完成名下从属共享的多选勾选与保存后，系统自动返回候选主机列表，该主机显示 `[✓] 已配置` 标记且不可重复选择，用户可继续选择第二台主机录入备选顺位，或选择“完成主机配置并继续”。
3. **Given** 用户首次运行向导且当前未连接网络存储，**When** 用户在主机候选列表中选择“跳过主机配置”，**Then** 系统不强制要求录入任何主机，直接流转至更新检查策略设置，并允许生成合法的空主机配置文件。
4. **Given** 用户在向导中完成了主机与共享的配置，**When** 向导进行到“后台服务部署确认”环节且用户选择“暂不部署/稍后手动管理”，**Then** 系统成功将配置持久化保存，并在终端输出友好的完成提示后安全退出，坚决不向系统写入或加载任何后台服务。
5. **Given** 用户在向导中完成了主机与共享的配置，**When** 用户选择“立即部署并启用后台自动挂载”，**Then** 系统保存配置并正确安装、注册且立即启动后台守护服务。

## 用户故事 2 - 根除挂载点命名污染与临时后缀误伤（Priority: P1）

使用者无论是通过向导扫描导入、还是在日常管理中添加共享，系统推导的标准目标挂载点路径始终保持与 SMB 共享名完全一致（即 `/Volumes/<ShareName>`）。系统以 SMB URL 中的真实共享名作为单一真理来源，彻底根除由于本地卷宗卸载残留或挂载冲突而产生的 `/Volumes/Data-1` 等带临时数字后缀的配置污染；同时，对于使用者本身命名就带有数字的标准共享（如 `project-1`、`media-2`），系统精准识别并原样保留，绝对不发生误伤裁剪。

**Why this priority**: 临时后缀 `-1` 污染配置文件会导致后续自动挂载判定失效、系统卷宗路径混乱，严重破坏产品核心功能的可用性与配置的纯洁性。

**Independent Test**: 模拟在系统中存在历史卷宗冲突导致挂载在 `/Volumes/Share-1` 的情景，通过程序扫描或添加该 SMB 共享，检查最终写入配置文件的挂载点路径是否严格为 `/Volumes/Share`；同时对合法命名为 `smb://server/work-1` 的共享进行测试，验证其标准挂载点是否准确保留为 `/Volumes/work-1`。

**Acceptance Scenarios**:

1. **Given** 系统中存在因未干净卸载而挂载在 `/Volumes/Public-1` 的临时卷宗，其真实 SMB 地址为 `smb://192.168.1.100/Public`，**When** 用户通过程序扫描并添加该共享，**Then** 系统识别出真实的共享名为 `Public`，配置文件中记录的标准挂载点为 `/Volumes/Public`，彻底抹除 `-1` 临时后缀。
2. **Given** 用户在服务器上创建了合法带有连字符和数字的共享文件夹 `smb://192.168.1.100/data-1`，**When** 用户将其添加到主机从属共享中，**Then** 系统准确推导出标准挂载点为 `/Volumes/data-1`，绝不发生将合法 `-1` 误删或误裁为 `data` 的情况。

## 用户故事 3 - 日常配置管理与向导交互流统一（Priority: P2）

使用者在执行 `automnt --config` 进行日常配置维护时，享有与初始化向导完全一致的交互心智模型与操作流。日常管理以主机顺位列表为核心视图，提供直观清晰的“查看/新增/调整顺位/删除主机”能力；进入特定主机后，同样复用“扫描当前已挂载共享 ➔ 勾选添加 ➔ 手动输入兜底”的流程，彻底消除初始化向导与日常管理两套交互机制割裂、重复维护的问题。

**Why this priority**: 统一向导与日常配置的底层交互组件，不仅大幅削减重复维护两套交互逻辑的代码复杂度，更能使用户在不同使用阶段保持一致、流畅、无学习成本的操作体验。

**Independent Test**: 运行 `automnt --config`，依次执行查看主机列表、新增主机（复用已挂载卷倒推）、进入特定主机管理共享、调整主机顺位与删除主机操作，验证所有交互步骤与 `--init` 向导表现出一致的风格和数据结构。

**Acceptance Scenarios**:

1. **Given** 用户已有保存好的配置文件，**When** 用户运行 `automnt --config` 并选择“新增主机”，**Then** 系统呈现与向导相同的候选主机发现列表与手动输入选项，仅提示输入主机地址与可选别名（回车默认采用主机地址），成功添加后该主机追加到顺位末尾。
2. **Given** 用户在日常管理中进入某一台已配置的主机，**When** 选择“添加从属共享”，**Then** 系统自动过滤并列出当前挂载在该主机上但尚未加入配置的 SMB 共享供用户多选勾选。
3. **Given** 用户拥有多台主机配置，**When** 用户使用顺位调整功能移动某台主机的位置，**Then** 配置文件中的主机顺位立即更新，后台下一次网络唤醒探测时严格按照最新顺位进行排他探测。
4. **Given** 用户在日常管理中选择维护某台主机的从属共享，**When** 用户选择删除某一个已配置的共享，**Then** 系统将其从该主机的共享列表中移除并持久化更新配置，后续探测评估不再尝试挂载该共享。
5. **Given** 用户在向导或日常管理中选择手动添加未挂载的新主机，**When** 用户键入主机地址后，**Then** 系统仅提示输入可选别名（直接回车默认采用主机地址，严禁索取底层内部标识符 `id`），并在无法从已挂载卷倒推共享时，自动引导用户手动输入从属共享路径（格式如 `smb://host/share`），自动推导出标准挂载点完成添加。

## 用户故事 4 - 全局文本输入支持 Esc 键放弃并安全回退（Priority: P2）

使用者在向导或日常配置的任何需要输入文本的交互环节（例如手动输入主机地址、输入自定义端口、手动输入共享名等），若中途改变主意或误触进入，只需按下键盘的 `Esc` 键，即可立即放弃当前输入。输入提示行被优雅清理，程序安全回退到上一级菜单或上一个交互步骤，不留存任何半成品脏数据，也不会粗暴地抛出异常或终止退出整个程序。

**Why this priority**: 命令行交互中如果误触后无法回头，只能强行乱打字符或通过中断键强退丢失全部前置操作，严重影响交互流畅度。支持 Esc 放弃回退是专业命令行软件必备的交互容错品质。

**Independent Test**: 在终端中启动 `automnt --config` 或 `automnt --init`，进入任意需要手动键入字符串的提示行（如添加新主机），按下 `Esc` 键，验证终端提示是否立即取消并平稳回到上一层菜单，不产生崩溃或脏配置。

**Acceptance Scenarios**:

1. **Given** 系统正在提示“请输入主机 IP 或域名”，**When** 用户未输入内容直接按下 `Esc` 键，**Then** 系统立即取消输入操作，终端输出“已取消”，并返回上级菜单。
2. **Given** 用户在输入框中已键入部分字符，**When** 用户按下 `Esc` 键，**Then** 系统放弃已输入的字符缓冲区，终端清理当前输入行并返回上一级。
3. **Given** 程序运行在非标准交互终端（如自动化脚本、管道或输出重定向环境中），**When** 输入机制检测到标准输入非交互式终端，**Then** 自动安全降级为标准流式行读取模式，杜绝终端属性配置错误导致的程序异常。

## 用户故事 5 - 允许空配置与后台安全休眠（Priority: P3）

使用者在日常管理中删除了最后一台主机导致配置列表为空时，系统将该状态视为合法的“空配置/待配置”，不再武断地将其判定为“配置文件损坏”，允许用户保存退出。后台服务或单次运行在读取到空配置时，能够清晰记录一条静默休眠日志并正常退出当前评估轮次，不告警、不报错、不崩溃。

**Why this priority**: 将“0 台主机”与“损坏配置”等同，会迫使界面打补丁禁止删空主机，违背了配置自由的第一性原理。修复此问题让状态机边界更加清晰健壮。

**Independent Test**: 在日常配置菜单中依次删除所有主机，直至主机列表为空，选择保存并退出；随后手动触发一次挂载评估，检查退出状态码与日志输出是否为正常的安全休眠。

**Acceptance Scenarios**:

1. **Given** 用户在 `--config` 中删除了所有配置的主机，**When** 用户退出配置，**Then** 系统正常将空主机列表持久化，不抛出损坏警告，不强行阻止退出。
2. **Given** 配置文件中存在 0 台主机，**When** 后台服务因网络变化或登录被唤醒，**Then** 程序识别到无待挂载主机，打印提示并以状态码 0 正常结束本次评估，不报告错误。

## 用户故事 6 - 存量配置平滑升舱与历史数据洗涤（Priority: P3）

对于已有旧版本配置文件的现有使用者，新版程序在首次加载读取配置时，能够全自动、原地、无感地将包含“网络策略（profiles）”的旧格式数据结构，清洗并升舱转换为纯主机顺位模型；同时，若历史配置中存在由于旧版缺陷引入的 `/Volumes/xxx-1` 挂载点污染，程序在升舱过程中自动根据 SMB URL 提取真名并予以规整还原；旧配置中的描述名称自动映射为主机别名，既有的探测超时与 Spotlight 索引防护配置完整继承，既不破坏现有的自动挂载业务，也不需要使用者重新跑初始化向导。

**Why this priority**: 保证向下兼容性与顺畅升级体验是软件生命周期的核心契约，避免存量用户在软件升级后因配置断代而陷入服务中断。

**Independent Test**: 准备一份包含旧版 `profiles` 结构（包含描述、探活超时、Spotlight 索引防护设置）且含有挂载点 `/Volumes/Share-1` 的旧配置文件，运行新版程序，检查配置文件是否被平滑升舱为新版结构，验证挂载点是否被清洗还原为 `/Volumes/Share`，且原有主机别名、超时参数与防护属性完全保留。

**Acceptance Scenarios**:

1. **Given** 磁盘上存在 v3.0.0 及更早版本（含 `profiles` 结构）的旧版配置文件，**When** 新版本首次读取该文件，**Then** 系统自动提取其中的主机与共享关系，将原 `profile.description` 映射为新主机的 `alias`，将 `profile.timeoutMs` 与 `profile.preventSpotlightIndex` 原样继承，平滑转换并以新版规范原地保存，记录平滑升舱通知。
2. **Given** 旧配置文件中的某个共享挂载点为 `/Volumes/Music-1`，其 SMB 地址为 `smb://nas/Music`，**When** 系统执行升舱洗涤，**Then** 该共享的挂载点被准确修正为 `/Volumes/Music`。

## 边界与异常情况

- **终端环境非标准交互终端**：在自动化测试、脚本输入重定向或无交互的子进程管道中，基于终端控制字符的行读取功能无法配置原始字符捕获模式。系统必须自动探测终端环境，在检测到非标准交互终端时优雅降级为标准流式行读取模式，杜绝终端属性配置错误导致的程序崩溃。
- **主机探测排他性刚性保证**：首个顺位主机连通后，系统必须严格执行该主机的共享挂载并立即终止后续探测（排他性短路，绝不发起额外连接）；后续备选主机即使网络通畅，也坚决不得自动发起挂载。排他性探测规则不容妥协。
- **钥匙串凭据提示精准克制**：对于从当前已挂载卷宗倒推出来的主机，表明系统钥匙串中必然已存有可用凭据，此时系统绝对不展示任何保存密码的冗余提示；仅当使用者在向导或管理界面中手动新增一台未挂载的新主机时，才在末尾给予一次温和的提示。
- **主机网络不可达或超时**：在手动添加主机时，若系统检测到主机 445 端口无法连通，向使用者展示明确的警示信息，但允许使用者在知情的情况下选择“仍然添加该主机”。
- **共享重复添加防呆处理**：若使用者试图将已经从属于某主机的 SMB 共享再次添加，系统自动进行去重并给出已存在的提示，避免出现重复记录。
- **向导跳过主机配置的空配置落地**：若使用者在向导中选择跳过主机配置并完成后续更新策略设置，系统保存包含空主机列表的有效配置文件，并在退出时提示使用者后续可通过日常管理命令随时添加主机。

# 功能需求

## 核心业务需求

- **FR-001**: 系统 MUST 废除“网络策略”、“局域网直连/远程降级”等二分法概念及任何特定组网工具的专用检测逻辑，将配置体系与探测模型完全统一为“以主机（Host）为一等公民的顺位列表”。
- **FR-002**: 系统在后台自动评估与挂载触发时，MUST 严格按照配置中的主机列表顺位依次探测。只要排在前面的首个主机探测连通（445 端口可达），系统 MUST 立即对该主机从属的启用共享执行挂载评估，并坚决立即终止对后续所有主机的探测（排他性短路），维持强排他性。
- **FR-003**: 系统的初始化向导（`--init`）与日常管理（`--config`）MUST 共享同一套“主机与从属共享交互引擎”，支持“扫描活跃卷宗倒推候选主机 ➔ 点选主机 ➔ 循环登记从属共享 ➔ 标记完成返回列表”的主机优先交互流程，支持从属共享的添加与删除维护，支持手动录入未挂载主机与共享路径，并支持在初始列表中跳过主机设置。
- **FR-004**: 系统在计算任何 SMB 共享的标准目标挂载点时，MUST 严格以 SMB URL 中的真实共享名称推导出 `/Volumes/<ShareName>` 作为单一真实来源，不得直接采用已挂载卷宗在本地冲突时生成的临时带数字后缀路径，且不得误伤合法带数字的标准共享名。
- **FR-005**: 系统在所有的交互式文本输入环节，MUST 支持基于终端字符捕获的轻量输入机制，当使用者按下键盘 `Esc` 键时，系统 MUST 立即丢弃当前输入、清空行缓冲并安全回退到上一级菜单。
- **FR-006**: 在初始化向导（`--init`）的后台服务部署确认环节，若使用者选择“暂不部署/稍后手动管理”，系统 MUST 仅保存配置文件，绝对禁止向系统安装、注册或加载后台守护进程。
- **FR-007**: 系统 MUST 允许配置文件中包含 0 台主机，并将其定义为合法的空配置状态。日常管理中 MUST 允许使用者删空所有主机并正常保存；后台运行在读取到空配置时，MUST 记录静默休眠信息并以状态码 0 安全退出。
- **FR-008**: 系统在加载旧版包含 `profiles` 结构的配置文件时，MUST 自动执行原地平滑升舱转换为纯主机顺位模型，将原描述转换为可选别名，原样继承超时及防索引属性，并对历史遗留的带 `-1` 等临时后缀挂载点进行自动规整与清洗。
- **FR-009**: 系统在添加主机时，对于从已挂载卷宗自动倒推的主机，MUST NOT 显示任何钥匙串密码保存提示；仅当使用者完全手动输入未挂载的新主机时，才允许显示温和的钥匙串提示。
- **FR-010**: 系统在引导使用者配置主机时，MUST NOT 索取或要求输入任何底层内部技术标识符（如旧版 `id` 等内部字段），MUST 仅提示输入可选的人类友好别名（`alias`）；当使用者直接按回车不输入时，系统 MUST 默认采用主机地址作为显示名称，彻底杜绝双重命名的多余输入。

## 关键实体

- **HostConfig（主机配置）**:
  - `host`: 主机 IP 地址或局域网/远程域名（必填，作为唯一标识与探测目标）。
  - `alias`: 人类友好别名/显示名称（可选，如“家庭高速 NAS”、“远程互联”，缺省时回退展示 host 地址；彻底替代旧版冗余的内部 id 与描述）。
  - `port`: SMB 探测端口，默认 445。
  - `timeoutMs`: 针对该主机的探活超时毫秒（可选，未设置时继承全局默认 1000ms）。
  - `preventSpotlightIndex`: 是否对该主机挂载点启用 Spotlight 防索引保护（布尔值，默认 true）。
  - `enabled`: 布尔值，控制该主机顺位是否参与探测。
  - `shares`: 该主机拥有的从属 SMB 共享列表。
- **SMBShareConfig（共享配置）**:
  - `name`: 共享显示名称。
  - `smbUrl`: 标准 SMB 访问路径（如 `smb://192.168.1.100/Data`）。
  - `mountPoint`: 标准本地目标挂载点（如 `/Volumes/Data`）。
  - `enabled`: 布尔值，控制该共享是否参与自动挂载。
- **AutomntConfig（顶层系统配置）**:
  - `version`: 当前配置的数据规范版本。
  - `hosts`: 主机顺位列表（有序数组，位置越靠前顺位越高）。
  - `globalSettings`: 全局运行参数（包括默认超时时间、挂载参数等）。
  - `updatePolicy`: 自动更新检查策略。

# 假设与约束

- **运行平台**: 仅支持运行在 macOS 27.0 或更高版本的 Apple silicon (arm64) 架构设备，不支持 Intel Mac 与旧版本系统（严格遵循项目平台边界约束）。
- **运行终端**: 假设使用者在支持标准 ANSI/POSIX 终端环境中运行交互向导；在非标准流式输入管道中自动优雅降级。
- **凭据机制**: 严格遵循项目宪法约束，SMB 凭据完全依赖系统钥匙串管理，程序内部严禁明文或密文落盘存储任何使用者密码。
- **顺位探测法则**: 顺位排他探测是系统的核心基石，首个连通主机挂载后即刻终止后续探测，不提供跨主机的并行挂载。
- **零外部编译依赖**: 继续严格遵循项目架构纪律，保持纯原生单文件零第三方依赖，不引入任何重型外部 TUI 或网络框架。
